# BU ITI — ระบบตรวจผลการพิจารณาสหกิจศึกษา

เว็บให้นักศึกษากรอกรหัสนักศึกษาเพื่อดูผลการพิจารณาของสถานประกอบการที่สมัครไว้
ข้อมูลอ่านจาก Google Sheet ที่อาจารย์ที่ปรึกษาใช้ติดตามผลอยู่แล้ว ไม่ต้องย้ายฐานข้อมูล

```
นักศึกษา → Next.js (Vercel) → API route ฝั่งเซิร์ฟเวอร์ → Google Sheet
```

เบราว์เซอร์คุยกับ Next.js เท่านั้น ไม่เคยเห็น URL ของชีตและไม่เคยได้รับข้อมูลของคนอื่น

## โครงสร้าง

| ไฟล์ | หน้าที่ |
|---|---|
| `src/lib/csv.ts` | อ่าน CSV ตาม RFC 4180 (ช่อง Status มีหลายบรรทัดและมีคอมมาข้างใน) |
| `src/lib/parse-sheet.ts` | แปลงตารางดิบเป็นรายการใบสมัคร จับคู่หัวคอลัมน์ และผูกสถานะจากแถวหัวข้อกลุ่ม |
| `src/lib/sheet.ts` | เลือกโหมดดึงข้อมูล + คัดกรองข้อมูลก่อนส่งให้เบราว์เซอร์ |
| `src/lib/stages.ts` | แปลงข้อความสถานะไทยเป็นขั้นตอนมาตรฐาน 5 ขั้น |
| `src/app/api/student/route.ts` | API ค้นหารายบุคคล (มี rate limit) |
| `src/app/page.tsx` | หน้าค้นหาสำหรับนักศึกษา — หน้าเดียวของทั้งเว็บ |
| `scripts/check-connection.mjs` | ตรวจว่าเชื่อมชีตได้หรือยัง บอกว่าติดตรงไหน |
| `apps-script/Code.gs` | ทางเลือกสำหรับกรณีที่ไม่อยากเปิดชีตเป็นสาธารณะ |

## สองโหมดในการดึงข้อมูล

โค้ดเลือกโหมดเองจาก environment variable ที่ตั้งไว้

| | โหมด CSV | โหมด Apps Script |
|---|---|---|
| ตั้งค่า | `SHEET_CSV_URL` | `APPS_SCRIPT_URL` + `APPS_SCRIPT_TOKEN` |
| ต้องติดตั้งอะไรเพิ่ม | ไม่ต้อง | ต้องวางสคริปต์และ deploy |
| สิทธิ์ของชีต | ต้องเปิดให้อ่านได้แบบสาธารณะ | ชีตเป็นส่วนตัวได้ |

ถ้าตั้งไว้ทั้งคู่ โหมด CSV จะถูกใช้ก่อน

## ติดตั้ง

### 1. หา gid ของแท็บที่ต้องใช้

เปิดแท็บนั้นในเบราว์เซอร์แล้วดูเลขหลัง `#gid=` ในแถบที่อยู่

ของชีตปัจจุบัน:

| แท็บ | gid | ใช้ทำอะไร |
|---|---|---|
| `comfirm_data` | `1793111820` | แท็บที่ใช้แสดงผล — มีแถวหัวข้อกลุ่ม `สถานะ :` คั่นเป็นบล็อก |
| `อาจารย์ที่ปรึกษา` | `882980091` | ใช้เติมชื่ออาจารย์เมื่อคอลัมน์ในแท็บหลักว่าง (ไม่บังคับ) |

> **Publish to web เปิดได้ทีละแท็บ** ถ้าเปิดเฉพาะ `comfirm_data` แท็บอาจารย์จะตอบ 401
> ให้ปล่อย `SHEET_ADVISOR_CSV_URL` ว่างไว้ แล้วกรอกชื่ออาจารย์ลงคอลัมน์
> `อาจารย์ที่ปรึกษา (ชั่วคราว)` ในแท็บหลักแทน — แอปอ่านคอลัมน์นั้นก่อนอยู่แล้ว

### 2. เปิดสิทธิ์ให้อ่านได้

เลือกอย่างใดอย่างหนึ่ง — อ่านหัวข้อ PDPA ข้างล่างก่อนตัดสินใจ

- **Share › General access › Anyone with the link › Viewer** — ง่ายที่สุด แต่เปิดทั้งไฟล์
- **File › Share › Publish to web › เลือกเฉพาะแท็บ › CSV** — เปิดเฉพาะแท็บที่เลือก
  ไฟล์ยังเป็นส่วนตัวอยู่ URL ที่ได้จะเป็นแบบ `/pub?gid=...&single=true&output=csv`

### 3. ตั้งค่าและตรวจ

```bash
npm install
cp .env.example .env.local
```

แก้ `SHEET_CSV_URL` ใน `.env.local` ให้ตรงกับ gid ที่ต้องการ แล้วตรวจ:

```bash
npm run check -- 1650705328
```

สคริปต์จะไล่ตรวจตั้งแต่ตัวแปรสภาพแวดล้อม รูปแบบ URL สิทธิ์การอ่าน โครงสร้างตาราง
ไปจนถึงทดลองค้นหาจริง และบอกวิธีแก้เมื่อเจอปัญหา ผ่านแล้วค่อย:

```bash
npm run dev
```

### 4. Deploy ขึ้น Vercel

```bash
git push
```

ที่ vercel.com → **Add New › Project** → เลือก repo นี้ → ใส่ Environment Variables ให้ครบ
(`SHEET_CSV_URL`, `SHEET_ADVISOR_CSV_URL`, `SHOW_SENSITIVE_FIELDS`) ทั้ง Production, Preview และ Development

`vercel.json` ประกาศ `"framework": "nextjs"` ไว้แล้ว จึงไม่ต้องพึ่งการตรวจจับอัตโนมัติ

> **ถ้าเจอ error `No Output Directory named "public" found`** แปลว่าโปรเจกต์บน Vercel ถูกตั้ง
> Framework Preset เป็น "Other" แก้ที่ **Settings › Build and Deployment › Framework Settings**
> → เลือก **Next.js** และปิดสวิตช์ Override ของ Build Command กับ Output Directory ให้หมด

## PDPA

หลักที่ระบบยึด: **นักศึกษาหนึ่งคนเห็นได้เฉพาะข้อมูลของตัวเองที่ค้นหาเท่านั้น**

สิ่งที่ทำไปแล้ว:

- **ไม่มีหน้าภาพรวมหรือสถิติรวม** และไม่มี endpoint ที่ดึงข้อมูลทั้งชุดออกมาได้
  API มีทางเดียวคือค้นหาทีละรหัส
- **ไม่ส่งข้อมูลอ่อนไหวออกจากเซิร์ฟเวอร์** — เบอร์โทรศัพท์, GPA และลิงก์ Google Drive
  ที่เก็บ Resume/Transcript (คอลัมน์ที่ในชีตเขียนกำกับเองว่า "เอกสารส่วนบุคคล ห้ามเปิด")
  ถูกตัดทิ้งใน `src/lib/sheet.ts` ก่อนตอบกลับ ไม่ได้แค่ซ่อนใน UI
- **ปิดบังอีเมลบางส่วน** (`dan*******@bumail.net`) พอให้เจ้าของยืนยันว่าเป็นของตัวเอง
- **ไม่ให้ search engine เก็บ index** (`robots: noindex`)
- **จำกัดจำนวนคำขอ** 20 ครั้ง/นาที ต่อ IP กันการไล่ยิงรหัสทีละเลข

### ความเสี่ยงที่ยังเหลืออยู่ — สองข้อ

**1. การเปิดชีตเป็นสาธารณะ**

โหมด CSV ต้องให้ชีตอ่านได้โดยไม่ล็อกอิน ถ้าเลือกแบบ *Anyone with the link*
ใครก็ตามที่ได้ลิงก์ไปจะเห็น **ทุกแท็บทั้งไฟล์** รวมถึงเบอร์โทร GPA และลิงก์เอกสารส่วนบุคคล
การที่เว็บไม่แสดงข้อมูลเหล่านั้นไม่ได้ช่วยอะไร เพราะคนเปิดชีตตรงได้อยู่ดี

ทางที่ปลอดภัยกว่าโดยยังได้ความง่ายเท่าเดิมคือ **Publish to web เฉพาะแท็บเดียว**
ไฟล์หลักยังเป็นส่วนตัว เปิดออกไปเฉพาะแท็บที่เลือก

ปลอดภัยที่สุดคือกลับไปใช้โหมด Apps Script ซึ่งชีตไม่ต้องเปิดสาธารณะเลย

**2. ยืนยันตัวตนด้วยรหัสนักศึกษาอย่างเดียว**

รหัสนักศึกษาเป็นเลขที่เพื่อนร่วมชั้นรู้กันอยู่แล้ว ใครที่รู้รหัสของเพื่อนจะเปิดดูชื่อ
บริษัทที่สมัคร และบันทึกของอาจารย์ได้ ทางแก้ที่ตรงกับข้อมูลชุดนี้ที่สุดคือ
ล็อกอินด้วยบัญชี Google ของมหาวิทยาลัย แล้วจับคู่กับคอลัมน์ `Viewer_Email` ที่มีอยู่แล้วในชีต

ถ้ายอมรับความเสี่ยงและต้องการให้แสดงข้อมูลอ่อนไหวด้วย ตั้ง `SHOW_SENSITIVE_FIELDS=true`

## จุดที่ระบบยืดหยุ่นไว้แล้ว

- **รหัสนักศึกษา** รับได้ทั้ง `1650703844` และ `1-65-07-0384-4` (ตัดอักขระที่ไม่ใช่ตัวเลขทิ้ง)
- **ชื่อคอลัมน์** จับคู่แบบ "มีคำนี้อยู่ในหัวคอลัมน์" ไม่ใช่เทียบตรงตัว สลับตำแหน่งคอลัมน์ได้
- **แถวหัวข้อกลุ่ม** `สถานะ : ...` ใช้กำหนดสถานะให้ทุกแถวที่อยู่ใต้มัน และข้ามแถวหัวตารางที่วางซ้ำกลางชีต
- **ข้อความสถานะ** จับคู่ด้วยคำสำคัญตามลำดับความเฉพาะเจาะจง (ดู `MATCH_RULES` ใน `src/lib/stages.ts`)
  ถ้าอาจารย์เพิ่มสถานะใหม่ที่ไม่รู้จัก ระบบจะแสดงข้อความดิบแทนการเดาผิด
- **บันทึกของอาจารย์** บางคนยาวหลายสิบบรรทัด หน้าเว็บจึงย่อไว้ 6 บรรทัดแล้วกดขยายได้

## ข้อจำกัดที่ควรรู้

- CSV ก้อนหนึ่งราว 200KB จึง cache ไว้ในหน่วยความจำ 120 วินาที (`SHEET_CACHE_SECONDS`)
  แก้ชีตแล้วเว็บจะตามภายในราว 2 นาที
- cache แยกตาม instance ของ Vercel นักศึกษาคนแรกที่เข้ามาหลัง cache หมดอายุจะรอราว 2-3 วินาที
- Rate limit เก็บใน memory ของแต่ละ instance กันคนกดรัวได้ระดับหนึ่ง แต่ไม่ใช่การป้องกันแบบจริงจัง
  ถ้าต้องการของจริงให้ย้ายไปใช้ Vercel KV หรือ Upstash Redis (`src/lib/rate-limit.ts`)
